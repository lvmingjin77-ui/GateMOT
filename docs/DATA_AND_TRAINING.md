# Data preparation and training

## Directory layout

Each dataset uses MOTChallenge format:

```text
DATA_ROOT/
  train/SEQ/img1/000001.jpg
  train/SEQ/gt/gt.txt
  test/SEQ/img1/000001.jpg
  annotations/                 # generated by prepare_data.sh
```

SportsMOT and DanceTrack also have `val/SEQ/`. Numeric image filenames with six or eight digits are supported. GT rows contain `frame,id,x,y,width,height,mark,class,visibility` for MOT17/MOT20. Images and GT remain in their original directories.

## Half training and validation

MOT17, MOT20 and BEE24 use the same temporal split. For a sequence of N frames, the first `floor(N/2)` frames form `halftrain`, and the remaining frames form `halfval`. Every frame appears in exactly one half. Original frame numbers are retained. Previous-frame inputs are selected within the same half, including at sequence boundaries.

```bash
export DATA_ROOT=/path/to/MOT17
scripts/prepare_data.sh mot17 --splits halftrain halfval
```

This writes `annotations/halftrain.json` and `annotations/halfval.json` using only `train/`. A test directory is not required. For MOT20 or BEE24, change the dataset argument and `DATA_ROOT`.

```bash
# Fit on the first half.
ANN_NAME=halftrain NUM_GPUS=2 scripts/train.sh mot17

# Track the second half with the saved model.
SPLIT=halfval \
LOAD_MODEL=exp/tracking.ctdet/mot17_halftrain_qattn_s317/model_last.pth \
scripts/test.sh mot17 --output_dir results/mot17_halfval
```

`model_last.pth` is generated by training. It is not a separate download. Numbered checkpoints are also saved, and any selected epoch can be passed through `LOAD_MODEL`. Run settings are recorded in `run_config.json`.

Default experiment names are `<dataset>_<split>_<head_type>_s<seed>`. Set `EXP_ID` for a separate run. `GLOBAL_BATCH` is the total batch across `NUM_GPUS` processes. Resume with the same experiment name and `--resume --load_model /path/to/checkpoint`.

The default MOT17/MOT20 boundary changed from the earlier `floor(N/2)+1` split. Regenerate both JSON files together. Use the original annotations when evaluating an older checkpoint against its original validation split, or pass `--half-split legacy` to regenerate the earlier boundary.

## Full training and official splits

For MOT17, MOT20 and BEE24:

```bash
export DATA_ROOT=/path/to/MOT17
scripts/prepare_data.sh mot17 --splits train test
ANN_NAME=train NUM_GPUS=2 scripts/train.sh mot17
SPLIT=test LOAD_MODEL=exp/tracking.ctdet/mot17_train_qattn_s317/model_last.pth \
  scripts/test.sh mot17 --output_dir results/mot17_test
```

For SportsMOT and DanceTrack:

```bash
DATA_ROOT=/path/to/SportsMOT scripts/prepare_data.sh sportsmot
DATA_ROOT=/path/to/DanceTrack scripts/prepare_data.sh dancetrack
```

These commands convert the official `train`, `val`, and `test` splits. Train with `scripts/train.sh sportsmot` or `dancetrack`; evaluate with `SPLIT=val scripts/test.sh <dataset>` and the corresponding `DATA_ROOT` and `LOAD_MODEL`. Full-train and half-train experiments use different output directories.

## Evaluation

```bash
git clone https://github.com/JonathonLuiten/TrackEval.git third_party/TrackEval
git -C third_party/TrackEval checkout 12c8791b303e0a0b50f753af204249e622d0281a

DATASET=mot17 SPLIT=halfval DATA_ROOT=/path/to/MOT17 \
TRACKERS_FOLDER=results/mot17_halfval scripts/eval_hota.sh
```

The evaluation wrapper uses exactly the frames in `halfval.json`. It copies and consistently renumbers the selected GT and prediction rows into a separate evaluation directory. Frames with no detections still count. Source GT is unchanged. `SPLIT=val` selects an official validation split, and `SPLIT=test` selects the test split.

Set `TRACK_EVAL` for an existing evaluator installation. Use a new `--output_dir` for each tracking run and a new `EVAL_DIR` when rerunning evaluation. Local evaluation requires GT. Submit MOT-format results to the official evaluator for hidden test sets.
