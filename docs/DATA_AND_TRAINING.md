# Data preparation and training

Run from the repository root after [installation](../README.md#installation). The four main experiments use complete training splits and test-set inference. Temporal half-splits are optional development tools, not a prerequisite for running the main experiments.

## Directory layout

Use an absolute `DATA_ROOT` pointing to a dataset in MOTChallenge format:

```text
DATA_ROOT/
  train/SEQ/img1/000001.jpg
  train/SEQ/gt/gt.txt
  val/SEQ/...                 # official SportsMOT validation split
  test/SEQ/img1/000001.jpg
  test/SEQ/gt/gt.txt           # only when test GT is available
  annotations/                # generated by prepare_data.sh
```

For SportsMOT, use the downloaded archive's `dataset/` directory. Numeric JPEG filenames with six or eight digits are supported. Images and GT remain in place; conversion writes JSON manifests selecting the frames.

MOT17/MOT20 GT rows contain `frame,id,x,y,width,height,mark,class,visibility`. BEE24 and SportsMOT are single-class tracking datasets. Test conversion reads images only and does not read test GT.

For MOT17, conversion includes all sequence directories present under each split, including DPM/FRCNN/SDP variants. GateMOT predicts its own detections and does not read `det.txt`. Keep the sequence set consistent across runs.

## Main experiments

Select one dataset and its root:

| `DATASET` | Example `DATA_ROOT` | Train JSON | Test JSON | Backbone |
|---|---|---|---|---|
| `bee24` | `/path/to/BEE24` | `train.json` | `test.json` | DLA-34 |
| `mot17` | `/path/to/MOT17` | `train.json` | `test.json` | DLA-34 |
| `mot20` | `/path/to/MOT20` | `train.json` | `test.json` | DLA-34 |
| `sportsmot` | `/path/to/SportsMOT/dataset` | `train.json` | `test.json` | DLA-60 |

Then run the shared workflow:

```bash
export DATASET=mot17 DATA_ROOT=/path/to/MOT17
scripts/prepare_data.sh "$DATASET"
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"

export LOAD_MODEL=exp/tracking.ctdet/${DATASET}_train_qattn_s317/model_last.pth
export TRACKERS_FOLDER=results/${DATASET}_test
SPLIT=test scripts/test.sh "$DATASET" --output_dir "$TRACKERS_FOLDER"
```

Preparation defaults to `train,test` for BEE24/MOT17/MOT20 and `train,val,test` for SportsMOT. To prepare only the full training and test splits, pass `--splits train test`. Training defaults to `ANN_NAME=train`, and inference defaults to `SPLIT=test`. SportsMOT uses official train, without automatically merging val into train.

For SportsMOT Table 2, use `exp/tracking.ctdet/sportsmot_train_qattn_s317/model_70.pth`. The other example paths use `model_last.pth` to demonstrate the workflow. The reported checkpoints and matching configurations are [coming soon](MODELS.md#coming-soon); the examples alone do not establish reproduction of the reported scores.

## Training settings

Defaults are in [train.sh](../scripts/train.sh):

| Dataset | Backbone | Epochs | Global batch | Learning rate | LR decay epoch |
|---|---|---:|---:|---:|---:|
| BEE24 | DLA-34 | 60 | 24 | 0.0002 | 40 |
| MOT17 | DLA-34 | 70 | 16 | 0.000125 | 60 |
| MOT20 | DLA-34 | 70 | 16 | 0.000115 | 60 |
| SportsMOT | DLA-60 | 80 | 20 | 0.00012 | 45 |

The supplementary table does not specify MOT20's batch size; the release currently uses 16. `NUM_GPUS` defaults to 1. `GLOBAL_BATCH` must be a positive multiple of it. Batch size changes can affect optimization. Additional flags can follow the dataset argument.

Experiment names default to `<dataset>_<training split>_qattn_s<seed>`, with seed 317. Set `EXP_ID` to name a separate run. Checkpoints and `run_config.json` are saved under `exp/tracking.ctdet/<experiment>/`. Numbered checkpoints are saved every five epochs and at the final epoch, alongside `model_last.pth`.

Resume the same experiment with:

```bash
DATA_ROOT=/path/to/MOT17 ANN_NAME=train NUM_GPUS=2 scripts/train.sh mot17 \
  --resume --load_model exp/tracking.ctdet/mot17_train_qattn_s317/model_last.pth
```

Resume restores model and optimizer state. [Implementation details](IMPLEMENTATION.md) describe losses, augmentation, association, and known differences from the submitted supplementary description.

## Optional validation

Without an official val split, a common MOT development protocol trains on the first temporal half of each training sequence and evaluates on the second. This supports parameter selection and controlled comparisons without using the test set. Once settings are fixed, the main test experiment trains a separate model on full train. [CenterTrack](https://github.com/xingyizhou/CenterTrack/blob/master/readme/GETTING_STARTED.md) provides separate half-training and full-training model workflows.

This optional protocol is available for BEE24, MOT17, and MOT20. Full-training main experiments do not require it.

```bash
export DATASET=mot17 DATA_ROOT=/path/to/MOT17
scripts/prepare_data.sh "$DATASET" --splits halftrain halfval
ANN_NAME=halftrain NUM_GPUS=2 scripts/train.sh "$DATASET"

export SPLIT=halfval
export LOAD_MODEL=exp/tracking.ctdet/${DATASET}_halftrain_qattn_s317/model_last.pth
export TRACKERS_FOLDER=results/${DATASET}_halfval
scripts/test.sh "$DATASET" --output_dir "$TRACKERS_FOLDER"
scripts/eval_hota.sh
```

Change `DATASET` and `DATA_ROOT` for BEE24 or MOT20. The first `floor(N/2)` frames form `halftrain`; the rest form `halfval`. Original frame numbers are retained, and previous-frame inputs stay within the chosen half. Only `train/` is needed. Regenerate both manifests together when changing the split policy. `--half-split legacy` preserves the earlier MOT17/MOT20 boundary at `floor(N/2)+1` for older annotations.

SportsMOT already has an official val split. Validate a model trained on its official train split with:

```bash
export DATASET=sportsmot DATA_ROOT=/path/to/SportsMOT/dataset
scripts/prepare_data.sh "$DATASET" --splits train val
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"

export SPLIT=val
export LOAD_MODEL=exp/tracking.ctdet/sportsmot_train_qattn_s317/model_70.pth
export TRACKERS_FOLDER=results/sportsmot_val
scripts/test.sh "$DATASET" --output_dir "$TRACKERS_FOLDER"
scripts/eval_hota.sh
```

Evaluate candidate checkpoints on validation data when selecting settings for a new experiment. Do not use test scores to select epochs or parameters. A full-training model evaluated on its own training half is not a held-out validation result.

## Evaluation

Install the pinned TrackEval version from the [README](../README.md#installation). Local scoring requires GT for the selected split. For example, with BEE24 test GT available:

```bash
DATASET=bee24 SPLIT=test DATA_ROOT=/path/to/BEE24 \
TRACKERS_FOLDER=results/bee24_test scripts/eval_hota.sh
```

`TRACKERS_FOLDER` must match the tracking command's `--output_dir`. The wrapper evaluates exactly the frames in the selected JSON, consistently renumbering copied GT and predictions in a separate evaluation directory. Empty prediction frames still count. Original GT and results are unchanged.

Metrics include HOTA, CLEAR (MOTA), and Identity (IDF1). Outputs are under `<TRACKERS_FOLDER>_eval_<SPLIT>/trackers/`. Set `TRACK_EVAL` to use an existing TrackEval installation. Use fresh tracking and evaluation directories for each run, or set `EVAL_DIR` to rerun metrics in a new directory. Hidden test data can be tracked without GT; scoring requires the benchmark's evaluation service or released annotations.
