# Data preparation and training

Run commands from the repository root after following the [installation instructions](../README.md#installation). Use an absolute `DATA_ROOT` path. The scripts accept `bee24`, `mot17`, `mot20`, `sportsmot`, and `dancetrack`.

## Directory layout

Each dataset uses MOTChallenge format:

```text
DATA_ROOT/
  train/SEQ/img1/000001.jpg
  train/SEQ/gt/gt.txt
  val/SEQ/...                 # SportsMOT and DanceTrack
  test/SEQ/img1/000001.jpg
  test/SEQ/gt/gt.txt          # when test GT is available
  annotations/                # generated by prepare_data.sh
```

SportsMOT's downloaded archive contains a `dataset/` directory. Point `DATA_ROOT` there. Images and GT stay in their original directories; conversion only writes JSON annotations. Numeric JPEG filenames with six or eight digits are supported.

GT rows use comma-separated `frame,id,x,y,width,height,mark,class,visibility` fields for MOT17/MOT20. BEE24, SportsMOT, and DanceTrack are processed as single-class tracking datasets. Test annotation conversion needs only images. Computing test-set metrics also requires `test/SEQ/gt/gt.txt`.

For MOT17, conversion includes every sequence directory under each split and does not filter DPM/FRCNN/SDP suffixes. The tracker predicts its own detections and does not read the provided `det.txt` files. Keep the sequence set consistent when comparing training runs.

## Half training and validation

BEE24, MOT17, and MOT20 use temporal halves of each training sequence. For a sequence of N frames, the first `floor(N/2)` frames form `halftrain`, and the rest form `halfval`. Every frame appears in exactly one half. Original frame numbers are retained. Previous-frame inputs are selected within the same half, including at its boundary.

```bash
DATA_ROOT=/path/to/BEE24 scripts/prepare_data.sh bee24 --splits halftrain halfval
DATA_ROOT=/path/to/MOT17 scripts/prepare_data.sh mot17 --splits halftrain halfval
DATA_ROOT=/path/to/MOT20 scripts/prepare_data.sh mot20 --splits halftrain halfval
```

This writes `annotations/halftrain.json` and `annotations/halfval.json` using only `train/`. Neither `val/` nor `test/` is required. For example, train and validate on MOT17 with:

```bash
export DATASET=mot17 DATA_ROOT=/path/to/MOT17
ANN_NAME=halftrain NUM_GPUS=2 scripts/train.sh "$DATASET"

export SPLIT=halfval
export LOAD_MODEL=exp/tracking.ctdet/mot17_halftrain_qattn_s317/model_last.pth
export TRACKERS_FOLDER=results/mot17_halfval
scripts/test.sh "$DATASET" --output_dir "$TRACKERS_FOLDER"
scripts/eval_hota.sh
```

Change the dataset, root, checkpoint, and output paths together for BEE24 or MOT20. The README includes [the validation settings for all four main datasets](../README.md#validation).

The default MOT17/MOT20 boundary changed from the earlier `floor(N/2)+1` split. Regenerate both JSON files together. Use the original annotations when evaluating an older checkpoint against its original validation split, or pass `--half-split legacy` to regenerate the earlier boundary.

## SportsMOT

SportsMOT uses separate official train and validation directories:

```bash
export DATASET=sportsmot DATA_ROOT=/path/to/SportsMOT/dataset
scripts/prepare_data.sh "$DATASET" --splits train val
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"

export SPLIT=val
export LOAD_MODEL=exp/tracking.ctdet/sportsmot_train_qattn_s317/model_last.pth
export TRACKERS_FOLDER=results/sportsmot_val
scripts/test.sh "$DATASET" --output_dir "$TRACKERS_FOLDER"
scripts/eval_hota.sh
```

Both scripts select DLA-60 automatically. Training requires `pretrain/dla60-24839fc4.pth`. This workflow does not require the official test split.

## Training settings

The default settings are defined in [train.sh](../scripts/train.sh):

| Dataset | Backbone | Epochs | Global batch | Learning rate | LR decay epoch |
|---|---|---:|---:|---:|---:|
| BEE24 | DLA-34 | 60 | 24 | 0.0002 | 40 |
| MOT17 | DLA-34 | 70 | 16 | 0.000125 | 60 |
| MOT20 | DLA-34 | 70 | 16 | 0.000115 | 60 |
| SportsMOT | DLA-60 | 80 | 20 | 0.00012 | 45 |

`ANN_NAME` selects the training JSON and defaults to `train`. `NUM_GPUS` defaults to 1. `GLOBAL_BATCH` is the total batch across all processes and must be a positive multiple of `NUM_GPUS`. Adjust GPU count and batch size to available memory. Changing these can change optimization behavior; retain the settings when comparing runs. Other training flags can be passed after the dataset argument.

The default experiment name is `<dataset>_<split>_<head_type>_s<seed>`, with `head_type=qattn` and `seed=317`. Checkpoints are stored under `exp/tracking.ctdet/<experiment>/`. Set `EXP_ID` for a separate run. Full-training and half-training experiments have different names.

Training saves `model_last.pth`, numbered checkpoints every five epochs and at the final epoch, and the resolved settings in `run_config.json`. Evaluate candidate checkpoints on validation data to select one. The examples use the last checkpoint to demonstrate the workflow; it is not automatically the best model or the checkpoint behind a manuscript result.

Resume the same experiment with:

```bash
DATA_ROOT=/path/to/MOT17 ANN_NAME=halftrain NUM_GPUS=2 scripts/train.sh mot17 \
  --resume --load_model exp/tracking.ctdet/mot17_halftrain_qattn_s317/model_last.pth
```

Resume restores model and optimizer state. See [implementation details](IMPLEMENTATION.md) for losses, augmentation, association, and differences between the released defaults and the submitted supplementary description.

## Test-set inference

After model selection, prepare the full training split and train a separate model for BEE24, MOT17, or MOT20. Each block below is independent.

```bash
# BEE24
export DATASET=bee24 DATA_ROOT=/path/to/BEE24
scripts/prepare_data.sh "$DATASET" --splits train test
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"
SPLIT=test LOAD_MODEL=exp/tracking.ctdet/bee24_train_qattn_s317/model_last.pth \
  scripts/test.sh "$DATASET" --output_dir results/bee24_test
```

```bash
# MOT17
export DATASET=mot17 DATA_ROOT=/path/to/MOT17
scripts/prepare_data.sh "$DATASET" --splits train test
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"
SPLIT=test LOAD_MODEL=exp/tracking.ctdet/mot17_train_qattn_s317/model_last.pth \
  scripts/test.sh "$DATASET" --output_dir results/mot17_test
```

```bash
# MOT20
export DATASET=mot20 DATA_ROOT=/path/to/MOT20
scripts/prepare_data.sh "$DATASET" --splits train test
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"
SPLIT=test LOAD_MODEL=exp/tracking.ctdet/mot20_train_qattn_s317/model_last.pth \
  scripts/test.sh "$DATASET" --output_dir results/mot20_test
```

For SportsMOT, use the model from the official training split above:

```bash
export DATASET=sportsmot DATA_ROOT=/path/to/SportsMOT/dataset
scripts/prepare_data.sh "$DATASET" --splits test
SPLIT=test LOAD_MODEL=exp/tracking.ctdet/sportsmot_train_qattn_s317/model_last.pth \
  scripts/test.sh "$DATASET" --output_dir results/sportsmot_test
```

For BEE24, MOT17, and MOT20, select the epoch and settings using the half-split experiment, then use the corresponding checkpoint from full-training. For SportsMOT, select the checkpoint on its official validation split. The output directory contains one MOT-format `.txt` file per sequence, using original frame numbers.

## Evaluation

Install the pinned TrackEval version using the [README instructions](../README.md#installation). `TRACKERS_FOLDER` must match the tracking command's `--output_dir`. For example:

```bash
DATASET=mot17 SPLIT=halfval DATA_ROOT=/path/to/MOT17 \
TRACKERS_FOLDER=results/mot17_halfval scripts/eval_hota.sh
```

For BEE24 test data with GT:

```bash
DATASET=bee24 SPLIT=test DATA_ROOT=/path/to/BEE24 \
TRACKERS_FOLDER=results/bee24_test scripts/eval_hota.sh
```

The wrapper evaluates exactly the frames in the selected JSON. It copies and consistently renumbers the selected GT and prediction rows into a separate evaluation directory. Frames with no predictions still count. Source GT and tracking results are unchanged. Metrics include HOTA, CLEAR (including MOTA), and Identity (including IDF1). The output is written under `<TRACKERS_FOLDER>_eval_<SPLIT>/trackers/`.

Set `TRACK_EVAL` for an existing TrackEval installation. Use a new `--output_dir` for each tracking run. Evaluation also requires a fresh output directory; set `EVAL_DIR` to rerun metrics into another directory.

Local evaluation requires GT. Hidden test splits can be tracked but cannot be scored locally. MOT17/MOT20 benchmark submission and evaluation are currently closed according to the [MOTChallenge archive](https://motchallenge.net/data/MOT17/); use `halfval` for local evaluation.

## DanceTrack

DanceTrack is an additional experiment beyond the four main datasets. The manuscript reports HOTA 61.1, MOTA 89.8, and IDF1 64.3 with DLA-34. Prepare the official splits, train, and validate with:

```bash
export DATASET=dancetrack DATA_ROOT=/path/to/DanceTrack
scripts/prepare_data.sh "$DATASET" --splits train val
ANN_NAME=train NUM_GPUS=2 scripts/train.sh "$DATASET"

export SPLIT=val
export LOAD_MODEL=exp/tracking.ctdet/dancetrack_train_qattn_s317/model_last.pth
export TRACKERS_FOLDER=results/dancetrack_val
scripts/test.sh "$DATASET" --output_dir "$TRACKERS_FOLDER"
scripts/eval_hota.sh
```

For test inference, convert `--splits test` and use `SPLIT=test` with a new output directory.
